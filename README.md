# mcbackup

Versioned, deduplicated backups of Minecraft servers to Cloudflare R2 (or any S3 bucket),
with player-aware scheduling, pinned checkpoints and point-in-time restore.

Built for [MCSManager](https://mcsmanager.com) hosts: instances are auto-discovered, nothing
needs to be configured per server. Standalone directories and `.zip` archives work too.

Under the hood every snapshot is a [restic](https://restic.net) snapshot: content-addressed,
encrypted, and only changed chunks are uploaded. A 4 GB world costs 4 GB once; a play session
afterwards costs a few MB.

## What it does

- **Discovers** every MCSManager instance (reads `InstanceConfig/*.json`, finds `server.properties`
  even when a zip import left it one folder deep) and each instance's world folders.
- **Snapshots when it matters** — the daemon pings each server for its player count and watches
  file changes:
  - every 30 min while players are online
  - 10 min after the last player/world change (captures the end of a session)
  - at least once a day if anything changed
  - nothing changed → nothing uploaded
- **Consistent snapshots** — sends `save-off` / `save-all flush` through the MCSManager API before
  reading the world, and `save-on` after, so region files are never captured mid-write.
- **Checkpoints** — `mcbackup checkpoint <src> -m "spawn finished"` pins a snapshot forever; one
  snapshot a week is promoted automatically. Everything else is thinned to
  hourly / daily / weekly / monthly by a retention policy.
- **Time travel** — list history, diff two points in time, restore any snapshot by id or date into
  a folder, or rewind the live instance in place (server must be stopped; a pre-restore copy is kept).
- **Archives** — one-off imports of old server zips, pinned so they're never pruned.

## Install

```sh
git clone https://github.com/Antoinenz/mcbackup && cd mcbackup
sudo ./install.sh
```

Requirements: Linux with systemd, Python 3.11+, `restic`, `rsync` (the installer apt-installs the
last two if missing).

Then fill in `/opt/mcbackup/env`:

| variable | where to get it |
|---|---|
| `RESTIC_REPOSITORY` | `s3:https://<account-id>.r2.cloudflarestorage.com/<bucket>` — the account id is shown on the R2 overview page |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | R2 → *Manage API tokens* → token with **Object Read & Write** on the bucket |
| `RESTIC_PASSWORD` | generated by the installer. **Keep a copy** — without it the backups are unreadable |
| `MCSM_URL` / `MCSM_APIKEY` | MCSManager panel → user menu → API key. Optional; without it the flush step is skipped |

Any S3-compatible store works, not just R2 (`s3:https://s3.amazonaws.com/bucket`, MinIO, B2 …).

```sh
mcbackup init                          # create the repository
mcbackup discover                      # check what was detected
sudo systemctl enable --now mcbackup   # start the scheduler
```

## Usage

```
mcbackup status                                     online players, last snapshot, pending changes
mcbackup history [source] [--all] [-n 40]           timeline of snapshots (* = pinned)
mcbackup backup <source> [-m note]                  snapshot now
mcbackup checkpoint <source> -m "note"              pinned snapshot, never pruned
mcbackup diff <source> <a> [b]                      what changed between two snapshots
mcbackup restore <source> [snapshot] [--to DIR]     restore into a folder (default /opt/mcbackup/restores/…)
mcbackup restore <source> <snapshot> --in-place [--worlds-only]
                                                    rewind the live instance (refuses while it's running)
mcbackup import <path> --name <name> [-m note]      one-off backup of a directory or .zip archive
mcbackup prune                                      apply retention now
```

`<snapshot>` is a snapshot id, `latest`, or a date/time — `2026-09-01` means "the newest snapshot
from that day or before", `2026-09-01T14:00` is exact to the minute.

```
$ mcbackup history labubu-smp
id        when              source          kind       plyr  note
eda948de  2026-09-13 15:40  labubu-smp      *checkpoint   0  auto checkpoint
3c1f0a92  2026-09-14 20:30  labubu-smp       auto         3  3 online (world 412, player 6)
b7e20c11  2026-09-14 22:41  labubu-smp       auto         0  session ended (world 88, player 3)
bb093178  2026-09-15 09:02  labubu-smp      *checkpoint      castle finished
```

## Configuration

`/opt/mcbackup/config.toml` — see [`config.example.toml`](config.example.toml) for all keys.

```toml
[policy]
tick_seconds = 300           # how often the daemon looks at each instance
online_interval_min = 30     # while players are online: snapshot at most every N minutes
after_session_min = 10       # snapshot N minutes after the last player-related change
max_interval_hours = 24      # if anything changed at all, snapshot at least this often
auto_checkpoint_days = 7     # promote a snapshot to a pinned checkpoint weekly

[retention]                  # checkpoints and imports are always kept
keep_hourly = 48
keep_daily = 30
keep_weekly = 26
keep_monthly = 36

[[sources]]                  # anything outside MCSManager: a directory or a .zip
name = "old-server"
path = "/srv/archives/old-server.zip"
manual = true                # only backed up when you run `mcbackup backup old-server`
```

The default `exclude` list skips what's regenerable or huge and pointless to version: archives,
`logs/`, `cache/`, `libraries/`, `versions/`, plugin lib folders, BlueMap's web output, Distant
Horizons' LOD database. Excluded paths are also protected from deletion on in-place restores.

## How restores work

- **To a folder** (default): the snapshot is unpacked under `/opt/mcbackup/restores/<source>-<time>-<id>/`.
  Copy back whatever you need — a single region file, one player's inventory, a plugin config.
- **In place**: refuses if the server answers a ping or MCSManager reports it running. The current
  files are copied to `restores/<source>-pre-restore-<time>/` first, then the snapshot is synced over
  the live directory (`--worlds-only` limits it to the world folders). Start the server again from MCSManager.

Because the repository is plain restic, the standard `restic` tooling works on it as well:
`restic snapshots`, `restic mount`, `restic check`, etc. — source `/opt/mcbackup/env` first.

## Layout

```
/opt/mcbackup/
├── mcbackup.py     the tool
├── config.toml     policy, retention, excludes, manual sources
├── env             secrets (chmod 600)
├── state.json      last snapshot / activity per source
├── mcbackup.log
├── restores/       restore targets and pre-restore safety copies
└── tmp/            scratch space for archive extraction
```
