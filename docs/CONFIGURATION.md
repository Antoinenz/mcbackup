# Configuration reference

mcbackup reads two files from `/opt/mcbackup/`:

| file | purpose | committed? |
|---|---|---|
| `env` | secrets and endpoints, `KEY=VALUE` lines | never (mode 600) |
| `config.toml` | policy, retention, excludes, manual sources | never (copy of `config.example.toml`) |

Both are re-read by the daemon on every tick, so edits take effect without a restart.

## `env`

```sh
RESTIC_REPOSITORY=s3:https://<account-id>.r2.cloudflarestorage.com/<bucket>
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
AWS_DEFAULT_REGION=auto
RESTIC_PASSWORD=
MCSM_URL=http://127.0.0.1:23333
MCSM_APIKEY=
```

| variable | notes |
|---|---|
| `RESTIC_REPOSITORY` | Any restic backend works. For Cloudflare R2 the account id is on the R2 overview page; the bucket must already exist. For AWS use `s3:https://s3.<region>.amazonaws.com/<bucket>`; for a local disk `/path/to/repo`. |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | R2 → *Manage API tokens* → token with **Object Read & Write** limited to the bucket. |
| `AWS_DEFAULT_REGION` | `auto` for R2. |
| `RESTIC_PASSWORD` | Encrypts everything in the repository. Generated by `install.sh`. **Back it up outside the server** — there is no recovery without it. |
| `MCSM_URL` | MCSManager panel (not daemon) address. |
| `MCSM_APIKEY` | Panel → user menu → *API key*. Used to run `save-off` / `save-all flush` / `save-on` and to check instance state. Optional: without it snapshots are still taken, just without the flush. |

Values are exported to the environment before restic runs, so any other `RESTIC_*` or `AWS_*`
variable restic understands can be added here too (e.g. `RESTIC_COMPRESSION=max`).

## `config.toml`

### `exclude`

Top-level array of restic exclude patterns. Patterns without a `/` match a file or directory
name anywhere in the tree; patterns with a `/` are relative to the instance root.

```toml
exclude = [
  "*.zip", "*.tar", "*.tar.gz", "*.7z",
  "logs", "cache", "libraries", "versions", "crash-reports",
  "plugins/*/libs", "plugins/*/.cache", "bluemap/web",
  "plugins/DHSupport/data.sqlite",
  "session.lock", ".console_history",
]
```

The same list is passed to `rsync --exclude` on in-place restores, so excluded paths are
neither backed up nor deleted when rewinding. Keep this in mind if you remove an entry: files
matching it will start being versioned, and existing ones will be *deleted* by an in-place restore
of a snapshot that predates the change.

Things worth excluding are large, regenerable, or churn constantly: archives, JVM library caches,
map renderers' web output, Distant Horizons LOD databases, Plan/analytics databases if you don't
care about them.

### `[mcsmanager]`

```toml
[mcsmanager]
instance_config_dir = "/opt/mcsmanager/daemon/data/InstanceConfig"
ignore = ["__MCSM_GLOBAL_INSTANCE__"]
```

| key | meaning |
|---|---|
| `instance_config_dir` | Where the MCSManager daemon keeps one JSON per instance. |
| `ignore` | Instance nicknames or uuids that should never be backed up. |

### `[[sources]]`

Any number of extra sources outside MCSManager.

```toml
[[sources]]
name = "old-server"
path = "/srv/archives/old-server.zip"
manual = true
```

| key | meaning |
|---|---|
| `name` | Becomes the source slug (lower-cased, non-alphanumerics → `-`). |
| `path` | A directory, or a `.zip` archive. Archives are extracted to `tmp/` for the duration of the backup, and the server root inside them is located automatically. |
| `manual` | `true` (default): only backed up when you run `mcbackup backup <name>`. `false`: the daemon treats it like an instance — but with no port it can't ping for players, so only the file-change rules apply. |

### `[policy]`

```toml
[policy]
tick_seconds = 300
online_interval_min = 30
after_session_min = 10
max_interval_hours = 24
auto_checkpoint_days = 7
flush_before_backup = true
flush_wait_seconds = 5
```

| key | meaning |
|---|---|
| `tick_seconds` | Daemon loop interval. Each tick pings every instance and walks its file tree for mtimes — cheap, but don't go below ~60 s on a large host. |
| `online_interval_min` | With players online, snapshot at most this often. |
| `after_session_min` | With nobody online and player/world files changed, snapshot once this many minutes have passed since the newest change. This is what captures the state at the end of a session. |
| `max_interval_hours` | If *anything* changed since the last snapshot (plugin data, configs…) and none of the above fired, snapshot after this long. |
| `auto_checkpoint_days` | The first snapshot after this many days since the last checkpoint is tagged `kind:checkpoint` and pinned. |
| `flush_before_backup` | Run `save-off`, `save-all flush` before reading, `save-on` after. Needs `MCSM_APIKEY`. |
| `flush_wait_seconds` | Pause after `save-all flush` before reading files, to let the server finish writing. |

See [SCHEDULING.md](SCHEDULING.md) for how these combine.

### `[retention]`

```toml
[retention]
keep_last = 10
keep_hourly = 48
keep_daily = 30
keep_weekly = 26
keep_monthly = 36
```

Maps directly onto `restic forget --keep-*`, applied per source once a day by the daemon (or with
`mcbackup prune`). `keep_yearly` is also accepted. Snapshots tagged `kind:checkpoint` or
`kind:import` are always kept regardless of these numbers.
